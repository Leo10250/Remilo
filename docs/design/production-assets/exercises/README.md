# Bundled exercise illustrations

The current app's semantic surfaces and Focus frame govern presentation. These
illustrations use the owner's approved Front plank artwork as their style input;
historical scenic mockups do not supply page structure or branding requirements.

Use [profile-v2.json](profile-v2.json) for further production work. It declares
the generic exercise registry explicitly for every subject. The original
[profile.json](profile.json) remains immutable evidence for Front plank's initial
preparation. That promotion needed a local compatibility adapter because the
shared helper's generic registry adapter ignored a registry declared only in
profile defaults. The adapter resolved the same effective asset specification;
it preserved approval/hash checks, output confinement and source bytes. Later
assets use the normal helper with profile v2.

Each entry in [manifest.json](manifest.json) binds its original PNG, transparent
960 × 540 lossless WebP, exact prompt, performed visual review and individual
owner approval. Masters live in `assets/exercises/masters`; runtime exports live
in `assets/exercises`. Contain fitting downsamples without enlargement or
stretching. Untagged source pixels are explicitly interpreted as sRGB; this is
not a measured embedded color profile.

For this implementation task, the owner's 16 October instruction explicitly
approves existing and upcoming artwork and inclusion without further individual
questions. The One-arm dumbbell row approval binds that standing instruction to
its reviewed candidate and preview hashes. Earlier individual approvals remain
unchanged. Technical and visual review still apply before promotion.

The exact built-in ImageGen submissions are retained in the versioned prompt
files and copied preparation records. Candidate images and eight-surface review
boards remain under ignored `verification/local/artwork/exercises`. Immutable
review/approval records preserve their hashes; portable audit does not require
ignored preview images to remain available on a clean checkout.

The rejected face-pull candidate 2 used candidate 1 as an edit input. Its original
input/preparation/review metadata treated that ignored source as a relative live
resource. Those four records were archived byte-for-byte under the local
candidate's provenance archive rather than rewritten. The durable
[rejection index](records/cable-face-pull/rejected-candidate-02.json) retains their
original identifiers and hashes, plus the prompt and performed failed inspection.
The approved candidate 3 and its approval bindings are unchanged.

Only approved immutable IDs enter `src/ui/exercise-illustrations.tsx`. Users
select an illustration explicitly. Exercise names, equipment and weights never
select one automatically; unknown references keep authored text and omit the
image region. Approval of an illustration does not establish clinical exercise
validation, runtime accessibility or signed-phone acceptance.

Asset inventory, active versions and provenance belong in the registry. Current
implementation and remaining approval status belong only in
[the backlog](../../../backlog.md).
